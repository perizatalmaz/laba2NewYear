# days-to-new-year

Программа на Go, которая считает, сколько дней осталось до Нового года. Можно посчитать от сегодняшнего дня или от любой даты. Високосные года учитываются.

Сделано в рамках практического задания по Go. Каждая лабораторная лежит в своей папке, код программы в каждой папке в одном файле. Сторонних библиотек нет, только стандартная библиотека Go.

## Что нужно для запуска

- Go версии 1.24 или новее (https://go.dev/dl/)
- Git, если клонируете репозиторий
- Docker, только если хотите запустить в контейнере

Проверить, что Go установлен:

```
go version
```

## Что где лежит

```
lab1/lab1.go         лаба 1, функция подсчёта дней и вывод в консоль
lab2/lab2.go         лаба 2, та же программа

lab5/lab5.go         лаба 5, HTTP сервер
lab6/lab6.go         лаба 6, тот же сервер
```

Сама функция `DaysUntilNewYear` везде отдельно от вывода и от HTTP: получает дату, возвращает число дней.

```

```

После запуска в терминале появится строка `server started` и сервер будет ждать запросы. По умолчанию порт 8080. Если он занят, можно указать другой:

## API

### Количество дней

```
GET /api/v1/days-until-new-year
GET /api/v1/days-until-new-year?date=ГГГГ-ММ-ДД
```

Параметр `date` необязательный. Если его нет, считается от текущей даты. Дата передаётся в формате `ГГГГ-ММ-ДД`, например `2024-02-29`.

Пример запроса (можно просто открыть в браузере):

```
http://localhost:8080/api/v1/days-until-new-year?date=2024-02-29
```

Ответ (код 200):

```json
{"date":"2024-02-29","new_year":"2025-01-01","days":307}
```

- `date` — дата, от которой считали
- `new_year` — дата Нового года
- `days` — сколько дней осталось

Для 31 декабря будет 1 день, а для 1 января 365 (или 366), потому что считается до следующего 1 января.

Если дата неправильная (другой формат, пустая или такого дня нет, например `2025-02-30`), сервер вернёт код 400:

```json
{"error":"invalid date \"14.10.2026\": expected format YYYY-MM-DD"}
```

Если отправить не GET запрос, будет 405. Если адрес не тот, будет 404.

### Проверка, что сервер работает

```
GET /healthz
```

Ответ (код 200):

```json
{"status":"ok"}
```

Сделал JSON, чтобы было так же, как в остальном API. Для мониторинга обычно хватает кода 200.

## CI (лаба 3)

Настроен GitHub Actions, файл `.github/workflows/ci.yml`. Запускается при push в `main` и на pull request. Что проверяется:

- форматирование (`gofmt`)
- `go vet`
- зависимости (`go mod verify` и `go mod tidy -diff`)
- сборка (`go build`)
- тесты (`go test`) с race detector и покрытием
- уязвимости через `govulncheck`
- сборка Docker образа

Если что-то из этого не проходит, CI падает.
